Predict how an anchored rectangle grows, then test its remaining motion

Rectangle constraint lab. Start with a 64 × 22 mm rectangular label blank. Predict where its left and right edges will be when the driving width changes to 80 mm. Compare a lower-left corner at the origin with a center at the origin.

Diagnose the freedom: keep width and height driving, but remove only the horizontal anchor. The rectangle can translate horizontally: 1 DOF remains. Remove the width instead while retaining both anchors and height; the corner-anchored rectangle's right edge can move, or the centered rectangle can grow symmetrically. Restore the conditions before testing the intended size edit.

Measure versus constrain: a top-edge reference dimension reports the current width and adds no equation. A second driving width that agrees with the first repeats the same equation: five displayed conditions can still have only four independent conditions. A different second driving width contradicts the first; there is no feasible rectangle, so the lab retains its last valid drawing rather than displaying an invented solution.

Bounded model: one closed axis-aligned rectangle, with four variables [left x, right x, bottom y, top y]. Closure, rectangular shape and orientation are built in. For a feasible set, DOF = 4 − rank (the independent equation count). Width and height stay between 1 and 120 mm; these bounds restrict admissible sizes and do not count as equality constraints. The lab projects toward the nearest solution of the active equalities and rejects changes outside its size range. It models no rotation or other sketch entities and does not reproduce a vendor's solver or error colors.

With JavaScript enabled, use the prediction, size controls and two draggable corners. Keyboard: focus a corner and press arrow keys; Shift changes the requested step from 1 to 5 mm. Undo diagnostic motion restores the previous drawing.

Count independent ways the geometry can still change

A degree of freedom (DOF) is one independent variable still available to change. Constraints remove freedom. Count the geometry's possible motion, not the number of icons.

Simple, isolated 2D entities before any dimensions or relations

Pointx and y position2
Nonzero line segmentx and y for each endpoint4
CircleCenter x, center y, radius3
Circular arcCenter x, center y, radius, two endpoint angles5

A circle's diameter dimension removes one DOF; its center can still move in two directions. Making its center coincident with the origin removes those two. A line with one endpoint at the origin still has length and direction to determine.

Why subtracting one per relation gives wrong answers

Coinciding a free point with a fixed point supplies two coordinate conditions. Putting a free point on a fixed line supplies only one. A repeated rule may supply no new independent condition. These counts assume ordinary, nondegenerate geometry: nonzero line lengths and positive radii. At special configurations, independent equations and usable motion require more care; do not assign a universal DOF reduction to each icon.

A driving dimension controls size; a driven dimension reports it

A driving dimension is a constraint: changing its value asks the solver to change the geometry while keeping the other rules. Length, angle, radius, diameter, and location dimensions can all supply constraints.

A driven or reference dimension measures a result already controlled elsewhere. It does not remove another DOF. For example, a circle whose size is set by a 24 mm driving diameter already has a 12 mm radius; a second driving radius dimension duplicates that control.

Use a relation for an enduring geometric rule and a dimension for the independent value you intend to change. Two lengths that must remain equal need an equal relation and one driving length, rather than two unrelated numbers that happen to match today.

Onshape automatically makes a newly added dimension driven if it would over-define the sketch. Check whether a displayed value is driving before expecting it to control geometry.

Software treatment of redundant dimensions

SOLIDWORKS can make a redundant dimension driven; its geometry-status help describes the driven dimension as gray. Onshape's Dimension tool distinguishes driving from driven dimensions and documents the automatic conversion. See Sketch Geometry Status and Onshape: Dimension.

For drawing presentation and dimension placement, see [[dimension-anatomy-and-placement]].

Read the sketch state in the software you are using

  • Under-defined / underconstrained: some position, orientation, or size remains free.
  • Fully defined / fully constrained: no free motion remains with the current driving values. Editing those values can still change the sketch.
  • Over-defined / overconstrained: dimensions or relations conflict or add control the solver treats as redundant. Repair the conflicting set.

Current vendor references for status colors

SOLIDWORKS: Sketch Geometry Status distinguishes several error states. Onshape: Troubleshooting Sketch Geometry documents geometry and constraint-icon colors. These are editing-state conventions, not a universal color code for every CAD display.

Fully define a sketch in a repeatable order

  • State what must stay aligned, centered, equal, or tangent when the size changes.
  • Choose the plane and an origin reference that suit that intent. Confirm the working units.
  • Draw the simplest useful entities. Check the automatic relations and remove unintended ones.
  • Connect the intended endpoints and apply the geometric relations that describe the shape.
  • Anchor the sketch's position to the origin or other stable references; control its orientation.
  • Add independent driving dimensions for the remaining sizes and locations.
  • Inspect the remaining free points and curves. Drag gently to diagnose motion, then undo the diagnostic move.
  • Resolve conflicts before adding more constraints. Inspect the whole sketch, including construction geometry.
  • Change one intended driving value, check that the sketch behaves correctly, then restore the value.

Fully defined is a useful check, not proof of good design intent. Fixing a misplaced point can remove freedom without giving it the correct location. A sketch can be completely constrained by dimensions that make future edits awkward.

Test design intent with a change, not just the starting shape

Fresh practice part: a circular inspection plate. Sketch two circular boundaries for an annular plate. Put their common center at the origin; use concentric and separate diameter dimensions of 46 mm and 18 mm. Increasing the outer diameter to 58 mm should leave the inner opening centered and unchanged in size.

Fresh practice part: a rectangular label blank. Use an axis-aligned rectangle with its lower-left corner at the origin, width 64 mm, and height 22 mm. Increasing the width to 80 mm should move the right edge while the left edge stays at the origin. If the intended part must grow equally left and right, choose a centered construction instead.

These two origin choices describe different editing behavior. There is no single best anchor for every part. Decide what should stay put before dimensioning.

Repair the unwanted rule, then check the intended change again

When an added dimension causes an error, inspect what already controls that measurement. Keep the relation or dimension that expresses the intended design. Remove the duplicate, or make a measurement driven if it is only there to report a result.

A horizontal line cannot also have a nonzero vertical separation between its endpoints. Equal circles cannot have different driving diameters. These are contradictions; adding still more dimensions will not solve them.

SOLIDWORKS offers Display/Delete Relations and SketchXpert for diagnosis. Onshape's Constraint manager filters constraints and dimensions to help locate problems. A suggested deletion is still a design decision: check what behavior you would lose.

Redundancy is not the same as contradiction

A repeated condition may agree mathematically yet be rejected as a second driving control. Some redundant geometric relations are tolerated: SOLIDWORKS documents a redundant perpendicular relation that leaves a sketch fully defined. Do not assume that every extra icon causes an error. See SOLIDWORKS: FAQ Sketch Relations and Onshape: Working with Constraints.
