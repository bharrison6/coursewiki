CAD describes the shape; CAM plans how to cut it

CAD supplies design geometry and drawings. CAM uses geometry plus the programmer's stock, tool, workholding, operation and cutting-data choices to calculate toolpaths. Depending on the operation, CAM may work from 2D profiles or a 3D model; a solid model is not always required.

[[img:cnc/cam-chain.svg|CAD geometry and dimensions flow to CAM operations and tools, then to a machine-specific post-processor, then to G-code reviewed against the actual setup.]]

A post-processor translates CAM output into the syntax and conventions for a particular machine/control combination. Selecting the wrong post can change tool calls, arc format, offsets or startup behavior. Review the posted code as well as the CAM preview.

Other ways to create a program

A short program can be written directly in a text editor. Conversational programming asks for feature dimensions at the control. Manual data input (MDI) lets the operator enter commands at the control, often for immediate execution. These routes still require correct modes, geometry and setup data; they do not bypass prove-out. Tormach's post-processor guidelines identify control-specific requirements.

Each prove-out aid answers a different question

Prove-out compares the intended operation, posted code and actual setup. Follow [[equipment-operating-procedure]] and [[machine-hazards]] for safety requirements; this page explains program-checking concepts, not a machine operating procedure.

Review the program against the setup before a supervised trial

  • Match the posted file and revision to the intended part, machine and post-processor.
  • Identify the active units, plane, distance mode and feed mode at each operation.
  • Compare work offsets, tool numbers and offset registers with the documented setup.
  • Trace the first approach, tool changes, cycle returns and final retract against the modeled stock and fixtures.
  • Check that the actual setup matches what the preview includes; resolve any discrepancy with the instructor before proceeding.
  • Identify the manual's dry-run, single-block and override behavior before using those functions in a supervised trial.
  • After an edit, repeat the affected checks; compare the first part's measured features with the drawing.

Practise interpretation with [[gcode-and-toolpaths]] and explore the existing 3D/WebGL milling lab in [[milling-operations]]. A successful simulation only establishes behavior within that model. It does not approve a program for a real machine.
