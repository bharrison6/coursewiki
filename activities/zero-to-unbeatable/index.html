    Value table

    Can experience alone teach a blank table to play?

    Before you start. Stage 1a’s model never changed. This model is a value table: one stored number per board position, every one of them zero to begin with. Reinforcement learning nudges those numbers after each win, loss and draw the table plays in training. No person tells it which square is good; only the app’s training burst updates it.

    Predict

    After one burst of 5,000 training games, will Era 1 be unbeatable, or still beatable?

    Try

    Press Show move scores in Era 0 (every score reads 0.00), then press Train the AI. Compare Era 1 with Era 0 in the change report under the training controls, and keep training until the proof line appears.

    Takeaway

    Reinforcement learning stores experience as a separate score for each position; only an exhaustive search over every game line, not a good record, earns the word unbeatable.

    Does playing the AI above train it?

    Demo 1 of 17 · Part one · Stage 3

    Neural Network

    Can one set of shared weights score boards it never practised on?

    Before you start. Stage 1b’s table kept a separate number for every position. A neural network keeps a smaller set of weights shared across every position and computes a score from them. Here it learns by supervised learning: it fits frozen scores that a fresh 1b table produced, so its targets came from another model, not from a person.

    Predict

    After training, will the network’s error on held-out positions (kept out of training) be about the same as on the positions it practised, or clearly higher?

    Try

    Press Create learning examples, read one weight in the network view, then press Train network. Compare the two error readings, then the separate playing score. Optional: switch the board to Ultimate tic-tac-toe for a learner whose inputs leave out part of the game.

    Takeaway

    Shared weights give the network an answer for a board it never practised on — which a table simply cannot do — and training on other boards makes that answer better. The error readings say how close the answer is to the teacher’s, not how well it plays.

    How it works

    Good Old-Fashioned Artificial Intelligence, or GOFAI, is a historical name for the symbolic AI tradition: programs that work with human-defined symbols, relationships and rules. This demo’s short hand-written priority list is one simple example, not the whole tradition.

    The ordered list acts like a chain of decision tests. If a test answers yes, it selects that action; if no, the program continues to the next test. A person wrote every test and its priority, so playing games does not revise this policy.

    Symbolic does not mean unlearned. Decision trees also route examples through tests, but their questions and branches can be learned from data. The representation and the way it was produced are separate facts: this particular chain was written by a person.

    Assumptions and simplifications

    • Eight rules stand in for a tradition that built expert systems with thousands; the point is the mechanism, not the scale.
    • When no rule applies the opponent picks a free square at random, so a shortened ladder’s exact losing game recurs by chance, not by design.
    • The exhaustive search follows every reachable reply including tied choices; it proves a property of this small game only.

    Sources

    • The ladder is src/rules.js; the search is OG.verifyPolicy in src/engine.js. Both ship inside this file and run in Settings → Run the full self-test.
    Boundary: a symbolic policy can be unbeatable on a small game. This demo does not claim that symbolic systems are always best, that they never scale, or that later models inevitably replace them.

    How it works

    1b’s model is a value table: one stored estimate for each board position, learned by tabular reinforcement learning. After actions lead to wins, losses, draws and later replies, rewards move the relevant estimates.

    Learning still has design choices made by people: the board representation, which game outcomes count as rewards, and the update rule. It is not given a rule that says “take the centre” or “block a row”.

    A positive score means the resulting board has tended to work out well for the player who just moved; a negative score means the opposite. It is a learned priority, not a spoken reason. Early in training the table sometimes tries a random legal move, which produces experience about choices it would otherwise ignore; as practice grows it relies more often on its strongest current score.

    Self-play does not make this self-supervised. Even when the table plays itself, game rewards still drive its updates, so its method is reinforcement learning.

    Assumptions and simplifications

    • Human play does not train this table; only the app’s training burst updates it. That is a design choice so the record strip measures the table rather than changing it — the same learner could have been wired to update after every game you play.
    • Tic-tac-toe is small enough that a table can hold every position (about five and a half thousand). Chess and language cannot be tabulated, which is why larger systems share parameters instead.
    • The unbeatable verdict is a property of one frozen era on this game, established by exhaustive search, not by the sampled games the montage shows.

    How it works

    This is a feedforward multilayer perceptron: information moves from 29 inputs through two hidden layers of 28 and 18 ReLU units to one linear score. The 29 inputs encode each of nine squares as empty, X or O, plus whose turn it is. The displayed score is clamped to −1 through +1 when read. It is not given rules for rows, forks or the centre.

    A fresh 1b value table first learns through 20,000 seeded reinforcement-learning games. Those learned estimates are frozen as target examples. The network then uses supervised learning to fit them; targets can come from another model rather than a person. The targets are not perfect-game answers, and a position the fresh table never visits can remain at its initial value of zero even when a solver would value it differently.

    Backpropagation computes how small changes to each weight would affect squared prediction error. The optimizer adjusts the current weights along that gradient, normalized by the squared length of the output gradient. It aims to reduce error; it does not evolve a population of candidate networks.

    One error is calculated from examples used for practice. The other is calculated from positions kept out of training. Related rotations and reflections stay together, so a near-copy cannot quietly turn the second number into a repeat of the first. Lower error is closer to the frozen learner; it does not guarantee a good answer on every new board.

    For each legal move, the app forms the resulting board and runs a forward pass through the network weights, then chooses from the best predicted boards. The frozen table is not consulted while you play. A weight is a connection strength; an activation is a signal for the current board; neither is automatically the goodness of a move.

    Assumptions and simplifications

    • The teacher is a fresh, seeded 20,000-game table, not a solved-game oracle; its estimates are the targets, imperfections included.
    • The network is deliberately small (1,381 parameters) so every weight can be read on screen; it is a worked example of the mechanism, not a claim about how large networks are trained.
    • This tab makes no automatic unbeatable claim. The policy diagnostic is reported as a reading alongside the sampled play; the wording would need a separate verification to change.
    • Ultimate tic-tac-toe (the optional extension) changes the representation: the inherited one-board table omits where a board sits on the meta-grid and where a move sends the opponent. A network given the same inputs omits them too; changing the architecture cannot recover information the representation never supplies.

    Sources

    • Teacher preparation, the grouped held-out split, the bounded updates and the measurements are src/net.js; src/neural.test.js checks them, including that play never consults the teacher.
    • The solved-variant result the extension quotes is cited in its own proof line, from ULT.SOLVED in src/ultimate.js.
    Boundary: lower error means closer agreement with the teacher, not guaranteed playing strength. People chose the inputs and the learning procedure; the network chose the weights.

    How it works

    An architecture is how a model is built: what it stores and how it computes an answer. A training method is how its adjustable parts change. The two are separate choices, and the model types on the next lens are a third, separate axis: the job.

    Linear and logistic models, learned decision trees, ensembles, nearest neighbours, support-vector machines and probabilistic models are other ways to represent patterns. Search and planning explore possible actions or future states; they are problem-solving approaches rather than another statistical family, and they can use models to evaluate the possibilities they explore.

    Assumptions and simplifications

    • The cards are a wider map, not a complete catalogue of AI; families overlap and one system can combine several.
    • The five methods are common textbook categories; real systems mix them (a self-supervised pre-training step followed by supervised fine-tuning is one ordinary combination). Pretraining and fine-tuning are stages that use these methods, not further methods.
    • “No training at all” is listed as a method so 1a has an honest place on the map; it is the absence of one.

    How it works

    A type is named by its job: what goes in and what comes out. The catalogue’s task names are mostly built that way (text-to-image, image-to-text, text-to-speech) or name the output (classification, detection, segmentation). Two models of one type are interchangeable at the job even when their architectures differ; two models of one architecture can be different types.

    The link back to this demo: 1c is a neural network scoring boards. The same idea — adjustable weights shared across every input — is what most catalogue types run on, with an architecture family (the transformer) that Hugging Face’s own framework page lists as serving text, vision, audio, video and multimodal jobs. It is not the only family. Generating images, audio and video leans on diffusion models, which Hugging Face keeps in a separate library, Diffusers, described on its own page as “pretrained diffusion models for generating videos, images, and audio”. Stable Diffusion XL’s card calls itself a “Diffusion-based text-to-image generative model” with a UNet inside; FLUX.1 [dev]’s card calls itself a “rectified flow transformer” — so the newest of them put a transformer under a diffusion-style training objective, which is stage 1d’s point again: architecture and method are separate facts. The tabular types are the other visible exception: their page names sklearn and xgboost, the tree and boosting families of stage 1d.

    Demo 1 of 17 opens Part one. Nothing comes before it. It hands forward one idea to Demo 2 (How a Language Model Works): a model is a representation that can be trained, and architecture, training method and model type are three separate questions to ask of any AI.

    One question for the session

    Where does an AI’s skill come from? Three models play the same board and each got its skill a different way. The top lens sorts models two ways: Model architecture (how it is built and trained — 1a to 1d) and Model types (what it does).

    “Architecture is how it is built. Training method is how it learns. Type is the job. Keep asking which one someone means.”

    1a · Symbolic AI (GOFAI) — 4 minutes

    Question

    Can a program play well without ever learning?

    Predict prompt

    Ask the room to press a prediction: with only the First 2 rules on, can you beat it? Take a show of hands before anyone plays.

    Activity

    1. 0:00 Press First 2 rules. Play one game; invite the room to find the fork. The Notice line and the panel name the rule that answered each move.
    2. 1:30 Press All 8 rules and play again. Point at the rule that fires each turn.
    3. 3:00 Open Details: the proof line reports the exhaustive search over every game playable against the ladder.

    Expected observation

    Two rules lose to a fork; eight rules have no losing line. The opponent explains every move by naming a rule, and nothing about it changes however many games are played.

    Check answer: a person wrote every rule and its priority; playing did not change them. The wrong option (“it learned the rules by playing”) is refuted by First 2 losing the same fork forever.

    Teaching limit

    GOFAI means Good Old-Fashioned Artificial Intelligence. This decision list can be drawn as a tree; here people wrote the tests, whereas decision trees can also be learned. Say “this small example”, not “symbolic AI”.

    1b · Value table — 5 minutes

    Question

    Can experience alone teach a blank table to play?

    Predict prompt

    After one burst of 5,000 games, will Era 1 be unbeatable or still beatable? Press a prediction.

    Activity

    1. 0:00 In Era 0 press Show move scores: every square reads 0.00. Play one short game; it moves at random.
    2. 1:00 Press Train the AI. Read the change report under the training controls: recorded scores before and after the burst.
    3. 2:30 Train again until the Notice line says verified unbeatable (usually burst 3 to 5). Switch the Opponent era back to Era 0 and forward again: the report follows the selection.
    4. 4:00 Open Details for the proof line.

    Expected observation

    Era 1 is still beatable; the scores moved but a losing line remains. A later era has no losing line in either role. Human play never changes the table; only the burst does.

    Check answer (“Does playing the AI above train it?”): no — here only the training burst updates the table; your games are scored, not learned from. Say the caveat out loud: that is this demo’s choice, not a law. The same table could have learned from every game you played, and real assistants can use what people type to train later versions, usually behind a setting. Details cites two vendors’ own pages (fetched 2026-09-16).

    Teaching limit

    A prediction of “unbeatable” is a claim about the table, settled by the exhaustive search, not by whether the room beat it: losing to a beatable era looks exactly like losing to an unbeatable one, and the reveal line says which one the search found. The table has one separate score per position, so it carries nothing to a different situation. Tic-tac-toe is small enough to tabulate; chess and language are not, which is why the next stage shares parameters.

    1c · Neural Network — 6 minutes

    Question

    Can one set of shared weights score boards it never practised on?

    Predict prompt

    After training, will held-out error be about the same as practised error, or clearly higher? Press a prediction; the reveal quotes the measured numbers.

    Activity

    1. 0:00 Press Create learning examples. A fresh table learner plays 20,000 seeded games; its estimates freeze as targets. This is the one slow step.
    2. 1:30 In the network view, pick a connection layer and a neuron; read one weight and its initialized value.
    3. 2:30 Press Train network. Compare the weight with its initial value, then the practised and held-out errors, then the separate playing score. Show move scores shows predictions for legal moves.
    4. 5:00 Optional: press Ultimate tic-tac-toe above the board to show a representation that cannot see the whole game; Standard board brings the network back.

    Expected observation

    The network is a feedforward multilayer perceptron (29 inputs, 28 and 18 ReLU units, one output) fitted by supervised learning to targets another model produced. Backpropagation supplies gradients; updates are normalized gradient steps. Shared weights give an answer for a held-out position; the error readings say how close, and neither is playing strength.

    Check answers: error measures agreement with the frozen table’s scores, which are themselves estimates; play is measured separately. 1b stores one number per position; 1c reuses 1,381 shared parameters for every board.

    Teaching limit

    Lower error means closer agreement with the teacher, not guaranteed playing strength; no automatic unbeatable claim is made. A position the fresh teacher never visited stays at zero — a limit of the examples, not proof the position is neutral. During play the network calculates its own scores without consulting the frozen table. Activations are responses to a board, not stored weights; a positive weight is not a good move.

    1d · Other architectures & training methods — 3 minutes

    Question

    What else can a model be, and how else can it learn?

    Predict prompt

    None on this stage. 1d is a map, not an experiment; nothing on it runs a result a prediction could be checked against. If you want a show of hands anyway, ask which of 1a, 1b, 1c learned from inputs paired with target answers, then press the Supervised learning card.

    Activity

    1. 0:00 The stage has three parts behind three buttons. Under Training methods, press each card. The card faces do not say which model used them; the press does: supervised → 1c, reinforcement → 1b, no training → 1a; the other three light nothing. Point at the one-line “used for” notes: pretraining is self-supervised, fine-tuning and distillation are supervised, RLHF is reinforcement — stages, not extra methods.
    2. 1:30 Switch to Other architectures and press a card: the line beneath says what that model stores and what it computes — linear models, decision trees, ensembles, nearest neighbours, support-vector machines, probabilistic models. Search and planning are named separately as problem-solving approaches.
    3. 2:15 Switch to Learning with no weight change: in-context learning, retrieval, search at decision time. Tie it to 1b’s check: a model can appear to learn in a session without changing. Press Search at decision time: 1a’s fork rules look one move ahead every turn; the demo’s exhaustive search checks players and never picks a move.

    Expected observation

    Architecture and training method are separate columns. 1c is a network trained by supervised learning; a network could equally be trained by reinforcement, and a table could be fitted to supervised targets.

    Check answer: no — the network is an architecture; supervised learning is how this one was trained.

    Teaching limit

    The cards are textbook categories, not a complete catalogue, and real systems combine them. Self-play is not self-supervision: 1b learns from rewards. Gradient training is not evolution.

    Model types — 3 minutes

    Question

    If “type” means the job, what goes in and what comes out?

    Predict prompt

    None on this stage: it is informational, and nothing on it runs a result a prediction could be checked against.

    Activity

    1. 0:00 Switch the top lens to Model types. Press three cards the room will recognise: text generation, text-to-speech, speech-to-text (automatic speech recognition). Each shows what goes in and comes out, then the catalogue’s own definition.
    2. 1:30 Press Image-to-3D: the job people call image-to-mesh. Follow Browse models on one card if you are online; the demo itself never fetches.
    3. 2:00 Scroll to Beyond one catalogue: eight major types the Hub list does not show — world models (Genie 3), video with sound (Veo 3.1), robot control (Gemini Robotics), protein structure (AlphaFold), weather (GenCast), background removal (NVIDIA Broadcast), character animation, free-viewpoint video — each linked to the model’s own page.
    4. 2:30 Scroll to the whole catalogue: every type Hugging Face lists, in its groups, with the model count on the fetch date.

    Expected observation

    A type is named by its input and output. Text generation and image-to-text are different types that can share one architecture family; tabular types are the visible exception, where the catalogue names tree and boosting libraries. The link back to 1c: a small network scoring boards is the same idea as the networks behind most of these types.

    Check answer: not necessarily — type is the job; one transformer may generate text and another caption images.

    Teaching limit

    The taxonomy and the counts are Hugging Face’s, fetched on the date shown on the stage; counts move daily. Other catalogues cut the jobs differently. The stage does not run any of these models.

    Misconceptions

    “A program that plays well must have learned.”1a plays unbeatable tic-tac-toe with no learning at all. Skill can be written down by a person; learning is one way to get it, not the definition of AI.
    “A long run of draws proves it is unbeatable.”Sampled games can miss a line. The app calls an era unbeatable only after searching every reachable game line in both roles. Open Details for the counts.
    “Playing against the table trains it.”Not here: human play is scored, not learned from, and every era is a frozen copy. But it is a design choice, not a rule — real systems can and sometimes do train on what users type.
    “I lost, so it must be unbeatable.”Beatable means a losing line exists, not that you found it. The search settles the verdict; your record only says how you played.
    “Low error means it plays well.”Error is agreement with a teacher whose estimates are imperfect. The playing score is a separate, fixed-seed measurement, and this tab never claims unbeatable.
    “Neural network is a kind of learning.”It is an architecture. 1c’s network was fitted by supervised learning; the same weights could be trained by reinforcement. Press the method cards in 1d.
    “Same architecture, same type.”Type is the job. Hugging Face files transformers under text generation, image-to-text, speech recognition and more. Ask what goes in and what comes out.

    Discussion questions

    • Which model stores separate values, and which shares weights? What does each choice make easy and hard?
    • Why does lower held-out error not prove unbeatable play? What measurement would?
    • Name an AI product you use. Which type is it, what might its architecture be, and how do you think it was trained? Which of the three can you actually tell from the outside?
    • The Ultimate extension: what information does the inherited representation leave out, and why can more training not put it back?
